# 系统更新说明

## 最近完成的修复和优化

### 1. 控制台窗口隐藏 ✅

**问题**：点击"启动播放系统"后会弹出命令行窗口，用户关闭窗口会导致整个系统终止。

**解决方案**：
- 启动器现在使用 `pythonw.exe`（如果可用）启动系统
- 使用 `STARTUPINFO` 和 `CREATE_NO_WINDOW` 标志隐藏控制台
- 系统在后台运行，不显示控制台窗口

**文件修改**：
- `src/ui/launcher.py` - 修改 `start_system()` 方法

**使用方法**：
1. 运行 `scripts/launcher.bat`
2. 点击"启动播放系统"
3. 系统在后台运行，不会显示控制台窗口

### 2. 看门狗功能完善 ✅

**问题**：播放窗口被关闭后，看门狗没有自动恢复播放。

**解决方案**：
- 改进播放状态检查逻辑，准确判断是否有任务应该播放
- 检查多种播放器类型（VLC、Selenium）
- 在调度器中添加 `get_current_task()` 和 `execute_task()` 方法
- 恢复时根据当前任务重新启动播放

**文件修改**：
- `src/core/watchdog.py` - 改进 `_check_playback()` 和 `_recover()` 方法
- `src/core/scheduler.py` - 添加 `get_current_task()` 和 `execute_task()` 方法

**工作原理**：
- 看门狗每30秒检查一次播放状态
- 如果有任务但没有播放活动，自动恢复
- 恢复时重新启动当前任务

### 3. 系统启动卡死修复 ✅

**问题**：启动播放系统后程序直接未响应。

**解决方案**：
- 将看门狗改为继承 `QObject`
- 使用 Qt 信号-槽机制进行跨线程通信
- 所有 GUI 操作在主线程中执行
- 移除非主线程的 GUI 操作

**文件修改**：
- `src/core/watchdog.py` - 继承 `QObject`，添加 `recover_signal` 信号

**技术细节**：
- Qt 要求所有 GUI 操作必须在主线程中进行
- 看门狗运行在单独线程中
- 使用信号在主线程中执行恢复操作

### 4. 浏览器关闭优化 ✅

**问题**：点击"停止播放系统"不能关闭浏览器。

**解决方案**：
- 实现三层关闭机制：
  1. 正常关闭 (`driver.quit()`)
  2. 强制关闭 (`driver.close()` + `driver.quit()`)
  3. 进程终止（使用 `psutil` 强制终止 Chrome 进程）
- 添加详细日志输出

**文件修改**：
- `src/core/selenium_player_auto.py` - 改进 `stop()` 方法
- `src/core/selenium_player.py` - 改进 `stop()` 方法

**建议**：
- 安装 `psutil` 以支持第3层关闭：`pip install psutil`

### 5. 网页直播启动优化 ✅

**问题**：播放网页直播时需要等待10-30秒检测和下载 ChromeDriver。

**解决方案**：
- 移除 webdriver-manager 的检测和下载逻辑
- 直接使用系统已安装的 ChromeDriver
- 启动速度从10-30秒降至1-2秒

**文件修改**：
- `src/core/selenium_player_auto.py` - 移除 webdriver-manager 相关代码

**要求**：
- 系统必须已安装 ChromeDriver
- ChromeDriver 版本必须与 Chrome 浏览器匹配

### 6. 任务重叠检查 ✅

**问题**：可以创建时间重叠的播放任务。

**解决方案**：
- 在保存任务前检查时间段重叠
- 检查星期交集
- 显示详细的冲突信息
- 编辑模式自动排除当前任务

**文件修改**：
- `src/ui/gui_manager.py` - 添加 `validate_and_accept()` 和 `check_overlap()` 方法

**检查逻辑**：
- 时间段重叠检查
- 星期交集检查
- 跳过已禁用的任务

### 7. 课程表视图优化 ✅

**问题**：任务时间不在整点时，课程表显示不准确。

**解决方案**：
- 根据实际任务时间动态生成时间段
- 使用 `setRowStretch()` 按时间段分钟数设置行高度权重
- 时间指示线仅在当前星期的列中显示
- 窗口大小调整时红线跟随移动

**文件修改**：
- `src/ui/schedule_calendar_view.py` - 改进时间段生成和显示逻辑

**效果**：
- 时间段精确显示任务的实际时间
- 行高度按时间段长度自动调整

### 8. 空时间表闪退修复 ✅

**问题**：当没有播放任务时打开课程表视图会闪退。

**解决方案**：
- 在 `refresh_view()` 开始时停止并清理定时器
- 在 `_calculate_time_position()` 中添加空时间段检查
- 在 `_update_time_indicator_position()` 中添加 `hasattr` 检查

**文件修改**：
- `src/ui/schedule_calendar_view.py` - 改进错误处理

## 看门狗功能说明

### 看门狗能做什么

✅ **可以自动恢复的情况**：
1. 播放窗口被用户手动关闭
2. 播放器崩溃或异常退出
3. 播放内容加载失败
4. 系统心跳异常（主循环卡死）

❌ **无法自动恢复的情况**：
1. 整个进程被终止（如关闭控制台窗口、任务管理器结束进程）
2. 系统断电或强制关机
3. Python 解释器崩溃

### 为什么无法恢复进程终止？

看门狗运行在播放系统进程内部，与主程序在同一进程中。当整个进程被终止时：
- 看门狗也随之终止
- 没有外部监控程序
- 无法自动重启

### 解决方案

**当前方案**：隐藏控制台窗口，避免用户误关闭
- 启动器使用 `pythonw.exe` 或隐藏标志
- 系统在后台运行
- 用户无法看到控制台窗口

**未来可能的方案**：
1. 添加系统托盘图标，显示运行状态
2. 创建外部监控程序（独立进程）
3. 使用 Windows 服务方式运行

## 使用建议

### 启动系统

**推荐方式**：
1. 运行 `scripts/launcher.bat`
2. 点击"启动播放系统"
3. 系统在后台运行

**不推荐方式**：
- ❌ 直接运行 `start_with_selenium.py`（会显示控制台）
- ❌ 使用 `python start_with_selenium.py`（会显示控制台）

### 停止系统

**正确方式**：
1. 在启动器中点击"停止播放系统"
2. 等待系统正常关闭

**不推荐方式**：
- ❌ 关闭控制台窗口（如果出现）
- ❌ 使用任务管理器强制结束
- ❌ 直接关闭播放窗口

### 查看运行状态

**方法1：查看日志**
- 位置：`logs/tv_system_YYYYMMDD.log`
- 实时查看：使用文本编辑器打开并刷新

**方法2：查看进程**
- 打开任务管理器
- 查找 `python.exe` 或 `pythonw.exe` 进程
- 命令行参数包含 `start_with_selenium.py`

**方法3：查看窗口**
- 空闲时应显示黑屏窗口（带时钟）
- 播放时应显示播放内容

## 配置文件

### 看门狗配置

文件：`config/config.py`

```python
SAFETY_CONFIG = {
    'enable_watchdog': True,        # 是否启用看门狗
    'check_interval': 30,           # 检查间隔（秒）
    'enable_heartbeat': True,       # 是否启用心跳检查
    'backup_content': 'backup.mp4'  # 备用内容路径
}
```

**调整建议**：
- `check_interval`: 默认30秒，可以调整为10-60秒
  - 更小：更快检测异常，但增加系统负担
  - 更大：减少系统负担，但延迟检测

### 其他配置

- `config/display_config.json` - 显示器配置
- `config/schedule.json` - 播放时间表
- `config/ui_config.json` - 界面配置

## 故障排除

### 问题1：启动后仍然显示控制台窗口

**可能原因**：
- 系统未找到 `pythonw.exe`
- Python 安装不完整

**解决方法**：
1. 检查 Python 安装目录是否有 `pythonw.exe`
2. 重新安装 Python，确保选择"Add to PATH"
3. 或手动编辑启动器指定 `pythonw.exe` 完整路径

### 问题2：看门狗没有恢复播放

**检查步骤**：
1. 查看日志 `logs/tv_system_*.log`
2. 搜索"检测到播放异常"
3. 搜索"系统恢复完成"
4. 检查 `config/config.py` 中 `enable_watchdog` 是否为 `True`

**可能原因**：
- 看门狗未启用
- 当前没有播放任务（空闲时段）
- 检查间隔太长

### 问题3：系统启动卡死

**已修复**，如果仍然出现：
1. 查看日志最后几行
2. 确认卡在哪个步骤
3. 检查该步骤的相关配置

### 问题4：浏览器无法关闭

**解决方法**：
1. 安装 `psutil`：`pip install psutil`
2. 重启系统
3. 如果仍然无法关闭，手动在任务管理器中结束 Chrome 进程

## 技术细节

### Qt 线程安全

- 所有 GUI 操作必须在主线程中进行
- 使用信号-槽机制进行跨线程通信
- 看门狗继承 `QObject` 以支持信号

### 进程管理

- 启动器使用 `subprocess.Popen` 启动主程序
- 主程序注册信号处理器捕获 SIGTERM 和 SIGINT
- 使用 `atexit.register()` 确保清理代码执行

### 看门狗机制

- 运行在单独线程中
- 定期检查播放状态
- 使用信号在主线程中执行恢复操作
